# Interface design notes

[Back to the tutorial](../README.md)

Maintainer reference. The student deployment does not require design work.

The AC215 course site uses React/Vite and shadcn controls with the Vantage direction from Hallmark: an editorial layout, clear typography, and a strong architectural introduction. The header places the Harvard shield beside a plain AC 215 label.

The sticky header opens five separate pages: Schedule, Policy, Tutorials, FAQs and Project Showcase. The Home tab returns to the SEC landing page. Its frosted surface has a solid fallback for reduced transparency. On phones, the logo, theme controls and native Menu fit on one row. Supported browsers animate page changes while the header stays steady. Keep the SEC journey, milestones and people on Home. Each destination has a complete static HTML file (`schedule.html`, `policy.html`, `tutorials.html`, `faqs.html`, `showcase.html`), its own title and description, and shared navigation, theme controls, footer and chat. Native links support browser history and direct loads. Flat filenames keep bucket and Nginx delivery simple. Load the home experience separately from the resource pages so they do not start the Three.js scene.

Use a month-filtered timetable for Schedule, a section index and readable rules/tables for Policy, a searchable lecture index for Tutorials, and searchable native disclosures for FAQs. Keep the full source wording and original resource links. The timetable snapshot preserves published rows and blank topics; its live schedule link remains available. Source hashes, retrieval details and publishing changes are recorded in `design-reference/course-showcase/pages-provenance.json`. Showcase says Coming soon beside a generated illustration of a poster-style demo session. Its feathering follows the transparent contour in both themes. Keep page headings compact enough to reach useful content quickly, and keep long mobile index labels to two visual lines without changing their accessible names. Native Menu navigation, FAQ disclosures, search and filters use the complete prerendered content. The header indicates the active page. A selected theme survives navigation; temporary chat turns do not survive a document change.

The original Three.js scroll scene uses solid meshes based on SEC visual references. It is an illustration, not a survey or an exact architectural model. A slow partial orbit reveals the courtyard, side and street-facing facade, then descends toward the established first-floor street-side entry. Keep that entry side and the room's placement and facing fixed when tuning camera motion. A short defocused fade passes through the exterior; conceal the change to the interior heading at peak defocus. One continuous interior curve bends toward the doorway, aligns before entering, passes through both door centers without stopping, and rises gradually after clearing them. Keep the exterior facade continuous; do not cut a window or invent an exterior doorway for the camera. The broad room is set deeper inside the building, with 300 seats in curved rows and three rear entrances. It has 240 seats in the main banks and 60 in two raised rear rows, separated by a cross-aisle and a clear center spine. The central route passes through a small vestibule between two white double-door sets. Each set opens as the camera approaches and reverses as it retreats. The projection screens are large, with the middle screen largest. Seating faces the direction marked in the instructor's reference.

Light, Dark, and System controls change the page, scene materials and actual lighting gradually over 700 ms. Reversing a theme change starts from its current visible state. Window lights are warm. Reduced motion uses still views and immediate theme endpoints. The initial theme is applied by `theme-init.js`. The public `sec-poster-light.png` and `sec-poster-dark.png` provide matching static fallbacks. The live model starts at the poster's size and framing. Navigation aligns target headings 40 px below the sticky desktop header, or 24 px below it on mobile. The classroom arrival shares that baseline while the scene remains pinned. Theme and Pause/Resume preferences persist in browser local storage for the same origin.

The build prerenders complete readable HTML. Load the scene separately from essential content. Keep the course page and poster readable without WebGL, motion, or JavaScript. Check keyboard focus, contrast, mobile layout, reduced motion, and theme changes.

The course guide expands from the bottom-right bubble into a floating window, including on the first click. Keep its dialog mounted closed initially so the opening animation runs. It must leave the page available and fit narrow screens. Minimize preserves the draft and temporary React-memory turns. Clear, reload, and navigation to another page discard them. Each backend request sends only the current question.

During a request, show one live work group with nested disclosures for actual file-read inputs and results. Collapse the activity before displaying the answer, and let readers reopen it. Show concise observable work, not private model reasoning. Clearly label the no-key path as notes preview; it performs keyword matching and actual file reads without an LLM agent.

Four public Markdown files in `backend/knowledge/` and `catalog.json` contain the guide's course information. Keep file provenance inside the compact tool disclosures. Do not add a source list beneath answers or a temporary-chat footer. The header contains only Clear and Minimize icons, with an accessible hidden dialog title. It has no visible title, subtitle or divider. Send/Stop belongs inside the input group at its lower right. The input has one highlighted border by default, with no additional focus ring on its textarea or container. Do not add a divider above it. The work summary uses a 32px row; individual read rows use 30px. Course discussion and lecture materials use the supplied Ed links and require course access. There is no login, upload, provider settings form, or saved conversation. Gemini authenticates through the VM's attached service account.

Milestone rows open compact modal reading windows with a blurred backdrop. The outer surface has no visible frame: a blurred paper-colored halo dissolves its perimeter. Keep internal divider lines. Light mode uses a paper-tinted backdrop that blends with the reading surface; dark mode uses a dark backdrop. Use a compact metadata/title header; retain its descriptive text for assistive technology. Keep the course page stationary beneath the dialog. Use native Base UI focus containment, Escape/Close dismissal and focus return. A section index scrolls the dialog's reading area; narrow screens use a horizontal section index. Opening and closing animate, with reduced-motion and reduced-transparency fallbacks. Render real lists and rubric tables, and retain the sample proposal and image.

The full milestone instructions live in `frontend/src/data/milestones/ms1.md` through `ms5.md`. Preserve their wording and meaning; restructure presentation or fix clear grammar only. Publishing frontmatter, duplicated page titles, empty template-link placeholders and the Staff feedback: TBD placeholder are omitted. The source commit hashes and editorial changes are recorded in `design-reference/course-showcase/milestone-provenance.json`. The chatbot's four course-note files remain concise summaries. Load the Markdown renderer when a dialog opens.

The hall's main-row spacing is 2.65, reducing the empty gap in front of the raised rear banks. Keep the 240 main and 60 rear seats, fixed entry, room transform and facing.

Teaching-team portraits rest in grayscale and reveal their original colors over 650 ms when hovered. Keyboard focus within a person’s card gives the same effect. The fade reverses on leaving, and the system reduced-motion preference removes the animation. Apply this presentation consistently to instructors and teaching staff; preserve the original images.
